# Security Policy

## Supported Versions

Security fixes are applied to the latest version on the `main` branch. Older versions may not receive security updates.

## Reporting a Vulnerability

Please do **not** open a public GitHub issue for a security vulnerability or include exploit details in a public discussion.

Report vulnerabilities privately through GitHub by contacting Sidharth S [@zidhuxd](https://zidhuxd.com/contact), or use GitHub's private vulnerability reporting feature for this repository when available.

When submitting a report, please include:

- A clear description of the vulnerability and its potential impact.
- The affected commit, version, or component.
- Reproduction steps or a minimal proof of concept.
- Any required configuration, permissions, or environment details.
- Suggested mitigations, if known.

Please redact credentials, tokens, personal data, and information about systems you do not own or have explicit permission to test.

## Response Process

The maintainer will acknowledge valid reports as soon as practical, investigate the issue, and coordinate remediation and disclosure with the reporter.

Please allow reasonable time for a fix before publicly disclosing the issue.

## Safe and Authorized Testing

WhaleRAT is intended only for authorized security research, defensive engineering, and academic study.

Test only on devices, accounts, and networks that you own or are explicitly authorized to assess.

Do not use this project to access, monitor, collect data from, disrupt, or modify systems without prior written permission.

The reporter must comply with all applicable laws and avoid privacy violations, service disruption, data destruction, persistence, or access to third-party data while validating a report.
